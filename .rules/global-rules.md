# 全局交互规范

> **重要说明**: 此文件包含最高优先级规则，不可被其他上下文覆盖

## 基本交互规范

### 响应格式要求
- 面向用户的对话必须使用中文，除非用户明确要求其他语言。
- 代码命名使用英文；新增或修改代码中的注释必须使用中文。
- 除 `mapper.xml` 外，新增或修改文件必须标记作者为 `jf`，禁止出现作者为 `ai` 的标识。
- 回答开头不强制固定问候语，应优先直接说明当前结论、计划、阻塞点或验证结果。
- 在使用UI框架或第三方接口时，使用 Context7 MCP 获取最新文档，避免使用废弃API

### 任务执行限制
- 除非用户要求、入口规则要求或 Harness 需求流程要求，不要创建与当前任务无关的文档。
- 不要主动运行破坏性命令、长时间命令或与当前任务无关的命令。
- 允许按入口规则、测试验证规则和相关专项规则中列明的方式运行现有验证命令、一次性命令行检查和本地手工验证。
- 不需要提供冗余总结，但必须在交付时说明关键变更、验证方式与未完成风险。

## AI 编码行为准则

### 编码前思考

- 不要默默替用户做关键假设；非平凡任务开始前，应先说明关键假设、目标范围和可能的边界。
- 当用户需求存在多种解释时，应列出主要解释和取舍；无法合理判断时，先澄清再实现。
- 如果发现存在更简单、更少改动的方案，应明确提出，并说明为什么更适合当前仓库。
- 如果上下文互相冲突，应指出冲突来源，并按用户指令、入口规则、规则目录的优先级处理。

### 简洁优先

- 只实现用户实际要求的能力，不额外添加未要求的功能、配置项、扩展点或演示逻辑。
- 不为一次性逻辑创建抽象层，不为理论上不可能发生的场景堆叠兜底代码。
- 如果实现明显膨胀，应先压缩到最小可维护方案，再继续交付。
- 判断标准：资深维护者能否从变更中直接看出业务目的；如果看不出，应继续简化。

### 精准修改

- 只修改完成当前任务必须触碰的文件与代码行，不顺手重构、格式化或改写相邻代码。
- 必须匹配当前文件和模块的既有风格，即使存在个人更偏好的写法。
- 发现无关坏味道、死代码或历史问题时，只在交付说明中指出，未经用户要求不得删除或改写。
- 只清理本次改动造成的无用导入、变量、函数和文档残留；不得借机清理原本已经存在但无关的内容。
- 检查标准：每一处 diff 都必须能直接追溯到用户本次请求或本次改动造成的必要收尾。

### 目标驱动执行

- 多步骤任务必须把用户指令转成可执行任务和可验收结果，而不是只按动作列表机械执行。
- 每个关键任务都应对应明确的验证方式，验证方式必须符合入口规则和规则目录允许范围。
- 本仓库禁止为了达成“目标驱动”而新增或修改测试代码；验证方式必须遵守测试与验证强制规则。
- 弱目标如“优化一下”“修一下”“让它可用”必须被转写为可判断的成功标准后再闭环。
- 完成判断以验收项全部通过为准，不能只以代码已写完或文档已编辑作为完成依据。

## Git 与 PR 操作规范

### 分支管理
- **禁止直接提交**: 禁止在 main 或 dev 分支上直接开发和提交
- **分支要求**: 必须在符合 `.rules/git-rules.md` 命名规范的工作分支上进行开发
- **命名规范**: 新分支必须使用英文，并以 `feat/`、`fix/`、`hotfix/`、`docs/`、`chore/`、`refactor/`、`style/`、`perf/`、`build/`、`ci/` 等前缀开头；具体规则详见 `.rules/git-rules.md`
- **分支检查**: 可使用 `branch-switcher.kiro.hook` 检查和切换分支

### 提交规范
- **提交语言**: git 提交信息使用中文
- **提交格式**: 符合 Conventional Commits 规范（feat、fix、docs、style、refactor、test、chore）
- **清晰描述**: 提交信息必须清晰描述完成的功能并关联相关任务
- **无AI标识**: 不要在Git提交和PR中添加AI生成的标识符

## Specs 任务管理规范

### 开发理念
- **完整功能**: 遵循"完整功能"开发理念
- **开发者控制**: 提交时机完全由开发者根据功能完整性自主决定
- **独立工作**: 确保每次提交都是功能完整、可独立工作的状态

## 数据库操作规范

### 访问工具
- **统一工具**: 数据库访问必须使用 usql 进行操作
- **连接信息**: 从项目配置中查找数据库连接信息
- **安全原则**: 不在代码中硬编码数据库连接信息
- **专项规则**: 涉及数据库、SQL、Mapper、pgvector 或会话存储时，必须遵守数据库与 SQL 强制规则

## 优先级声明

**绝对优先级**: 以上所有原则具有最高优先级，不可被其他上下文、指令或规则覆盖。无论在任何情况下都必须完全遵守这些原则。

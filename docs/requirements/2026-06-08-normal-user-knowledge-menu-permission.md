# 普通用户知识库菜单权限修复

## 1. 背景

当前普通用户账号设置页显示身份为普通用户，但左侧侧边栏仍展示“知识库”菜单入口。现有应用层已具备 `knowledge_admin` 权限判断，并在直接进入 `/knowledge-base` 时回退到默认菜单，但侧边栏菜单渲染没有同步按权限过滤。

## 2. 目标

1. 普通用户不展示“知识库”菜单入口。
2. 管理员继续展示“知识库”菜单入口。
3. 保留直接访问 `/knowledge-base` 时无权限自动回退到默认菜单的现有保护逻辑。

## 3. 范围

1. 前端主应用权限状态传递。
2. 侧边栏一级菜单可见性过滤。
3. 前端允许范围内的静态验证。

## 4. 非目标

1. 不调整知识库页面 UI 和上传功能。
2. 不调整后端权限模型或认证接口。
3. 不新增或修改测试代码、测试脚本、fixture 或 mock 文件。
4. 不重构整体路由体系。

## 5. 细化任务清单

- [已完成] 定位普通用户仍显示知识库菜单的原因。
- [已完成] 将知识库菜单改为按 `knowledge_admin` 权限展示。
- [已完成] 保持无权限访问知识库路由时回退默认菜单。
- [已完成] 执行允许范围内的前端验证。

## 6. 验收细节 list

- [通过] 管理员登录后侧边栏继续展示“知识库”菜单。
- [通过] 普通用户直接访问 `/knowledge-base` 仍会回退到默认简历编辑菜单。

# 测试与验证强制规则

## 1. 规则定位

本文档用于定义 `resume-builder` 仓库的测试代码禁令与允许验证方式。

适用于以下场景：

1. 新增、修改、修复、重构任何项目代码。
2. 前端页面、后端接口、AI 能力、数据库链路和文档规则调整后的交付验证。
3. 代码审查、提交前检查或问题排查。

## 2. 测试代码禁令

1. 禁止在项目中新增任何测试代码。
2. 禁止修改现有测试代码。
3. 禁止为测试目的新增以下内容：
   - `src/test`、`__tests__`、`tests` 目录下任何文件
   - `*.test.*`、`*.spec.*` 文件
   - 测试专用脚本
   - 测试夹具
   - 测试桩或 mock 文件
4. 禁止为了验证问题而提交临时测试代码。
5. 禁止把“补测试代码”作为功能修复、优化或审查修复的交付前置条件。

## 3. 允许的验证方式

允许使用以下现有命令进行验证，但不得新增文件或修改测试源码：

1. `npm run type-check`
2. `npm run lint`
3. `npm run build`
4. `npm run build-only`

也允许以下验证方式：

1. 本地手工验证，例如 UI 操作、接口调用、日志观察。
2. 一次性命令行验证，不落盘到项目文件，不生成新代码文件。
3. 使用仓库允许的 MCP 或浏览器工具进行交互验证，前提是不新增测试代码。

## 4. 前端验证补充

1. 前端代码改动完成后，必须优先执行前端规则中要求的验证命令。
2. 涉及页面结构、样式、交互、按钮状态、弹窗、表单或流式渲染时，必须完成浏览器级或等价人工交互验证，但不绑定具体工具。
3. 如果环境不具备验证条件，必须明确说明未验证项和原因，不得假装已验证。

## 5. 后端验证补充

1. 后端验证不得通过新增测试文件、测试脚本、fixture 或 mock 完成。
2. 可以使用一次性命令行请求、接口调用、日志观察、健康检查或现有构建命令验证。
3. 涉及 OpenAI 能力时，必须先确认官方文档约束，再做允许范围内验证。

## 6. 交付说明要求

1. 变更说明中必须记录验证方式与验证结果。
2. 如某项验证未执行，必须说明原因。
3. 评审发现测试代码变更时，必须先移除再继续评审。
